Главное (рабочий стек — через Docker)

  1) В корне репозитория:
       docker compose up -d
     (или: docker-compose up -d)

  2) Один раз доверить сертификат для https://localhost:3000 (см. ниже и блок «Ошибка сертификата в Word»), иначе Word не откроет надстройку.

  3) Открыть Word с надстройкой без магазина Office:
       .\sideload-word.ps1
     или двойной щелчок sideload-word.cmd
     Скрипт сам проверяет, что контейнеры pf-frontend / pf-backend запущены и что API/фронт отвечают,
     затем выполняет npm run dev:word (нужен Node.js и npm install в frontend при первом запуске).

  Ручной вариант без скрипта: cd frontend → npm install → npm run dev:word
  Отдельные команды: npm run register  |  npm run sideload:word
  Запасной вариант: загрузить frontend/manifest.xml через «Мои надстройки» в Word.

Проверка после старта:
  curl http://localhost:8000/health
  curl -k https://localhost:3000/
  Ожидается HTTP 200. Браузер на https://localhost:3000 покажет предупреждение о сертификате — это нормально до установки корня (см. ниже).

Бэкенд: http://localhost:8000
Фронт (надстройка): https://localhost:3000
Тот же UI по HTTP (без SSL, для проверки в браузере): http://localhost:3001
БД: localhost:5433

Ошибка nginx «400 Bad Request — The plain HTTP request was sent to HTTPS port»
  Значит открыли адрес с http:// на порту 3000. Порт 3000 только для HTTPS.
  Используйте https://localhost:3000/ или для HTTP — http://localhost:3001/

Ошибка сертификата в Word (жёлтая панель)

  Текст вроде: «Содержимое заблокировано, так как оно не подписано с помощью действительного сертификата безопасности»
  / «ОШИБКА НАДСТРОЙКИ» — это не баг кода, а WebView в Word: он не доверяет самоподписанному HTTPS для https://localhost:3000,
  пока сертификат не добавлен в хранилище «Доверенные корневые центры сертификации» (именно корневые, не «Промежуточные»).

  После установки сертификата: полностью закройте Word (все окна), откройте снова и нажмите «Перезапустить» в панели надстройки.

Способ A (автоматически), из корня репозитория — обычный PowerShell без администратора:
  powershell -ExecutionPolicy Bypass -File .\scripts\trust-localhost-cert.ps1
  (сертификат в хранилище текущего пользователя; если Word всё ещё не доверяет — тот же скрипт из PowerShell «От имени администратора»)

Способ 1 (вручную). Скопировать сертификат из контейнера и установить:
  docker cp pf-frontend:/etc/nginx/ssl/localhost.crt .
  Дважды открыть localhost.crt → Установить сертификат → Локальный компьютер →
  Поместить все сертификаты в следующее хранилище → Доверенные корневые центры сертификации.
  Закрыть Word полностью и открыть снова.

Способ 2. Открыть в браузере https://localhost:3000 → предупреждение о сертификате → Просмотр сертификата → Сохранить/экспорт →
  установить в тот же хранилище «Доверенные корневые центры сертификации». Перезапустить Word.

Если Word показывает «Не удалось загрузить надстройку. Проверьте подключение к сети» — чаще всего тоже не доверенный HTTPS; сначала шаги выше.

После установки сертификата нажмите в Word «Перезапустить» или снова загрузите надстройку (manifest.xml).

«Сбой запроса сведений о каталоге» / не открывается список надстроек из магазина

  Это сообщение обычно относится к каталогу Office (магазин Microsoft), а не к локальному manifest.xml.
  Причины: нет интернета, прокси/VPN, политики организации, блокировка доступа к сервисам Office.

  Что сделать:
  1) Не пытаться ставить эту надстройку через «Магазин Office» / общий каталог.
  2) Подключить локальный manifest вручную (sideload):
     Word → Вставка → Надстройки → у нижней части окна «Мои надстройки» / «Управление моими надстройками»
     → «Загрузить надстройку из файла» / «Upload My Add-in» → выбрать файл frontend/manifest.xml из репозитория.
     (Названия пунктов могут отличаться в зависимости от версии Word и языка интерфейса.)
  3) Центр управления безопасностью: Файл → Параметры → Центр управления безопасностью → Параметры центра…
     → «Надстройки» → разрешить использование надстроек из магазина (если политика не запрещает).
  4) Убедиться, что https://localhost:3000 открывается в браузере после доверия сертификату (см. выше).

Путь к манифесту в репозитории: frontend/manifest.xml
